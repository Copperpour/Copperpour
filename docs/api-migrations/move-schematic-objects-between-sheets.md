### `move_schematic_objects_between_sheets` moves circuit objects between sheets in `sch_hierarchy` (minor release)

The new `move_schematic_objects_between_sheets` moves UUID-selected symbols, wires, junctions, local and global labels, no-connect flags, text and text boxes from one single-instance sheet of a saved project to another by `offset_x_mm`, `offset_y_mm`. Symbol and pin UUIDs, references, unit membership, properties and footprint associations are kept; instance paths change to the destination sheet.

- The sheets may belong to different top-level schematics in one project. Use project-declared top-level instance UUIDs in sheet paths. Multi-root verification requires KiCad 10.0.7 or newer.
- A dry run by default. Apply takes the `plan_revision` of a current dry run as `expected_plan_revision`: a missing one is `invalid_argument`, a different one is `stale_target`, and nothing is written.
- When `kicad-cli` is missing, a dry run returns the schematic plan with `verification.status: "not_run"`; apply refuses as `plan_blocked`. An unreadable verification result is a refusal, not a pass. See [cross-sheet transfer](../CROSS_SHEET_TRANSFER.md) for other limits.
- The tool does not write the PCB. A move that would leave a footprint path stale, change an effective netclass, or require dependent net-name edits is refused. A rename also refuses if the project has custom PCB rules that the schematic checks cannot verify. Files the plan reads but does not change are held as read-set guards.
- If the plan depends on a PCB or library table not existing, the journal records that absence. Recover that transaction with a Copperpour version that supports version 2 journals.
- A failure before the transaction journal is written is a refusal (`invalid_argument`, `stale_target`, `unsafe_file_fallback`, `conflict` or `plan_blocked`), and an unfinished older journal is a `conflict` naming that journal. A write failure after that is `mutation_outcome_uncertain` and names the stopped file and the journal; `copperpour transaction recover` can finish the move if the guarded inputs still match. If the transaction completed but readback failed, inspect the saved project using the reported transaction ID.
